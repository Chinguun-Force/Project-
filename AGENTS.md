## Learned User Preferences

- User often communicates in Mongolian; use English only for foreign-tourist-facing UI (e.g. iOS PWA install guide).
- Prefer Supabase MCP for Supabase schema, migrations, and database debugging when available.
- Staff navigation: moderator login shows only the Moderator panel; admin login shows only Moderator and Admin (not the full traveler app menu).
- Points/balance UI uses `apps/nomad-go-v2/public/Shagai.png` (not inline SVG) with a flip animation when balance changes.
- Logout must redirect to the login page (tourist `/settings` Danger Zone and moderator shell); new registration must land on the dashboard.
- Show total points (Shagai balance) persistently beside the user profile in the shell.
- Use Nomad-Go branded loading: spinner for buttons/actions, skeleton for page/section loads, and post-login boot screen (`NomadBootScreen`) before dashboard on slow networks.
- Tours marketplace cards show image, title, short description, duration, price, and mission badges (top 2 highest-XP missions; overflow as +N).
- Dashboard shell: single Settings button (avatar + gear) to `/settings` (no profile dropdown); logout only in Danger Zone; Profile shortcut plus conditional Moderator/Admin links. Home (`app/(dashboard)/page.tsx`) shows profile-summary card plus 4-stat grid (Level, Streak, Quests, Rank) like `/profile`.
- Prefer platform-native / self-hosted solutions over third-party SDKs (e.g. Supabase's built-in email confirmation; self-hosted Web Push instead of OneSignal).
- Currency converter must be offline-first (localStorage cache after one online fetch); default input currency MNT with thousands separators so tourists can enter shop Tögrög prices.
- Mission sight cards show distance in km only (via `formatDistanceKm`); do not display radius; XP reward stays visible.

## Learned Workspace Facts

- Nomad-Go is an NX package-based monorepo (`apps/*`, `packages/*`, `libs/*`); primary app `apps/nomad-go-v2` (dev via `npm run dev:v2`): Next.js App Router in `app/`, shared code in `src/`; siblings include nomad-go-main, nomad-go-pwa, nomad-go-v3. Drizzle (`db/schema.ts`); introspect via `npm run db:pull:v2` (not Prisma). Shared libs: `@nomad-go/shared-ui`, `@nomad-go/gamification-xp`; root `.cursorrules` defines engineering standards.
- Gamified travel PWA backed by Supabase; quest/mission rewards flow through `grantUserRewardsAction`. tRPC routers in `apps/nomad-go-v2/api/router.ts` are stubs returning `{}` / `[]` / `null` (e.g. `progress.me`); real data comes from Supabase server actions in `src/app/actions/gameActions.ts` (e.g. `getUserProgressAction`).
- Four app roles only: admin (super admin), moderator (company staff), guide (company-hired), tourist.
- Domain model: `trips` → `rooms` (`room_code`) → `room_members` / `room_activities`. Tourist join: `joinRoomByCodeAction`; metadata `room_id`. Legacy `sessions` APIs return HTTP 410; admin **Departures** tab lists rooms; `moderatorActions.ts` removed. Room status `active`/`archived`, activity status `pending`/`in_progress`/`completed`; DB trigger `sync_room_status_from_activities` (migration `20260613233000_auto_archive_completed_rooms.sql`) auto-archives a room when all activities complete and reopens it on revert. Tourist dashboard (`getTouristActiveRoomAction`) surfaces only `active` rooms, so a finished journey disappears and the join-code input returns.
- Multi-tenant trips: `tenants` = travel company row; staff link via `profiles.tenant_id`. Guide hire: admin assigns `guide` role (may omit `tenant_id`); moderator invites unassigned guides via `guide_hire_requests`; guide confirms before `tenant_id` binds (migration `20260614150000_guide_hire_requests.sql`). Staff panels: `/moderator` (templates with `ImageUploadField` cover + mission search max 4 matches, team hire, `/moderator/company` profile edit, rooms); `/guide` (assigned rooms + pending hire invites); admin Companies tab creates tenants, assigns moderators, lists company moderators. Tours marketplace list/detail render `CompanyProfileCard`. Auth: role/tenant from `profiles`, XP/points from `users` (dual-table sync); email confirmation uses Supabase's built-in flow (`/auth/confirm`, `emailRedirectTo`, `auth.resend`; signup returns `needsConfirmation`).
- Tourist marketplace `/tours`: published `trips` only; join live group via room code on Home (`/`). Offline quests: Dexie `offline_submissions` for PHOTO, AUDIO, QR_SCAN, QUIZ, TIME_BOUND; sync via `POST /api/sync/quest-submissions`.
- Public-table RLS baseline: migration `20260614040000_enable_rls_baseline_public_tables.sql` (MCP-applied) enables RLS on 16 legacy/catalog tables — authenticated SELECT on content catalogs, self-access on user-owned rows, staff-only on deprecated sessions/timeline tables; admin writes use service role.
- Map and Shagai redeem shop are intentionally locked "Coming Soon": dashboard redeem card, map `CampCard` premium unlock, `AppLayout` Map nav item (`locked: true`), and `/map` placeholder page (direct URL still shows Coming Soon).
- Notifications are self-hosted Web Push (VAPID), not in-app and not OneSignal (fully removed): dedicated `public/push-sw.js` (separate from the next-pwa SW; needs `skipWaiting`/`clients.claim`), `push_subscriptions` table (RLS), client subscribe in `src/lib/notifications/pushClient.ts` gated by the Settings notifications toggle, `POST /api/notifications/subscribe`, server send via `src/utils/notifications/webPush.ts` (`sendPushToRoom`); triggers include activity start/complete and expedition-complete (guide notes pushed to room members).
- Tunnelled dev (ngrok) needs top-level `allowedDevOrigins` (supports wildcards, e.g. `*.ngrok-free.app`) for HMR/RSC plus `experimental.serverActions.allowedOrigins` for Server Actions (CSRF); avoid the `--host-header` rewrite.
- `users` table (`db/schema.ts`) has no streak column; daily streak is tracked client-side via localStorage in `src/lib/dailyStreak.ts`, tied to the Road Blessing daily check-in (`claimDailyCheckinAction`). Avoid a `gamification/` folder beside `src/lib/gamification.ts` (module-resolution ambiguity); put standalone lib helpers directly under `src/lib`.
- Mission catalog seed: 34 Mongolia sights in English at `apps/nomad-go-v2/supabase/seeds/missions-mongolia-sights.json`; `scripts/seed-missions.mjs` inserts rows; `scripts/compress-upload-mission-images.mjs` compresses raw photos from `supabase/seeds/mission-images/raw/` (filename = `image_slug`) and uploads to Supabase Storage.
